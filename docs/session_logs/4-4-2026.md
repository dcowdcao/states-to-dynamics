## Distance-Weighted L1 Verification

**Confirmed**: The Othello SpaDE experiment uses the same distance-weighted L1 penalty as the original Spade repo.

### Formula

$$\text{dist\_reg} = \frac{1}{B} \sum_b \sum_j \|x_b - \text{Ad}_j\|^2 \cdot f_j$$

### Original Spade Repo (`Original_Spade_Repo/functions/train_test.py`, lines 57-63)

- Regularizer explicitly named `'dist_weighted_l1'` (line 17)
- Documented as "distance-weighted L1 regularization on latent features (from the KDS paper)" (line 21)
- Implementation (using decoder weights, `encoder_reg=False`):
  ```python
  dist_penalty = (X.unsqueeze(1) - model.Ad.T.unsqueeze(0)).pow(2).sum(dim=-1)
  loss_reg = (dist_penalty * xlatent).sum(dim=-1).mean()
  ```
- Total loss: `loss = loss_mse + gamma_reg * loss_reg` (line 106)

### Othello SpaDETrainer (`spade_trainer.py`, lines 190-196)

- Implementation:
  ```python
  dist_penalty = t.cdist(x, self.ae.Ad.T).pow(2)
  dist_reg = (dist_penalty * f).sum(dim=-1).mean()
  ```
- Total loss: `loss = recon_loss + self.gamma_reg * dist_reg` (line 196)

### Equivalence

Both compute squared L2 distances between inputs and decoder atoms (`||x - Ad_j||^2`), multiply by feature activations (`f_j`), sum over features, and average over the batch. The only difference is the PyTorch idiom: `t.cdist(...).pow(2)` vs broadcast-subtract-square-sum. Mathematically identical.

### Comparison to Other SAE Regularizers

| SAE Type | Regularizer | Formula |
|----------|-------------|---------|
| Standard ReLU | Plain L1 | `sum_j \|f_j\|` |
| **SpaDE** | **Distance-weighted L1** | `sum_j \|\|x - Ad_j\|\|^2 * f_j` |
| JumpReLU | L0 | `sum_j 1(f_j > threshold)` |
| TopK | None (hard sparsity) | Top-k selection, auxk loss for dead neurons |
| p-Anneal | Lp^p with annealing | `sum_j \|f_j\|^p`, p: 1.0 -> 0.2 |

Combining all regularizer losses into a single W&B plot is **not meaningful** because the regularizers compute fundamentally different quantities with different units/scales. **Metrics that ARE directly comparable across all SAEs** (and should be plotted together):
- `mse_loss` — reconstruction error (same units)
- `l0` — number of active features
- `frac_variance_explained` — R² of reconstruction
- `frac_dead_neurons` — fraction of permanently inactive features

**Regularizer loss is only comparable within the same type**, e.g., across the 8 SpaDE sweep configs.

## Regularizer Loss Explainer

### L1 (StandardTrainer)
`reg = Σ_j |f_j|` — Penalizes total magnitude of all feature activations equally. Every active feature costs proportional to its value. Pushes toward fewer, smaller activations. Same as L1/Lasso in linear regression.

### Lp^p with p-Annealing (PAnnealTrainer)
`reg = coeff * Σ_j |f_j|^p, p: 1.0 → 0.2` — Starts as L1, then gradually lowers p toward 0. As p→0, `|f_j|^p` approaches the step function (L0 = count of active features). At p=0.2, activation 0.01 is penalized almost as much as activation 10.0 — penalty cares mostly about whether a feature is on, not how much. `sparsity_coeff` is adaptively adjusted as p changes.

### L1 on Gate (GatedSAETrainer)
`reg = Σ_j |f_gate_j|` — Same as L1, but applied to **gate activations**, not final features. Gated architecture has two paths: gate (which features turn on) and magnitude (how strong). Penalizing the gate decouples sparsity pressure from reconstruction quality.

### Lp^p on Gate with Annealing (GatedAnnealTrainer)
`reg = coeff * Σ_j |f_gate_j|^p, p: 1.0 → 0.2` — Combines gated architecture with p-annealing. Gets decoupled sparsity/magnitude (gating) plus approximate L0 penalty (annealing).

### Auxiliary Loss for Dead Features (TopKTrainer)
No sparsity regularizer — sparsity is **structurally enforced** (exactly k features active per input, always). `auxk_loss` is a reconstruction loss using only dead features, encouraging them to learn useful directions so they might become active later. Prevents feature collapse.

### Distance-Weighted L1 (SpaDETrainer)
`reg = Σ_j ||x - Ad_j||² · f_j` — Each feature's L1 penalty is **weighted by squared distance** between input x and that feature's decoder atom Ad_j. Nearby atoms are cheap to use; far-away atoms are expensive. Encourages a local, distance-based dictionary structure (each atom "owns" a region, similar to k-means/Voronoi). Unlike all others, this penalty is **input-dependent** — the same activation f_j incurs different costs depending on where the input is relative to the atom.

### Key Differences Summary

| Property | L1 | Lp^p Anneal | L1-Gate | Lp^p-Gate | TopK | Dist-Weighted L1 |
|----------|-----|------------|---------|-----------|------|-------------------|
| What's penalized | activation magnitude | activation count (as p→0) | gate magnitude | gate count (as p→0) | nothing (structural) | activation × distance |
| Input-dependent? | No | No | No | No | No | **Yes** |
| Encourages | small activations | few activations | few gates open | few gates open | exactly k features | use nearby atoms |
| Geometric structure? | No | No | No | No | No | **Yes** (locality) |

## Dead Neuron Resampling & Tracking Audit

### Resampling: OFF for All 6 Trainers

Every trainer in the pipeline has dead neuron resampling **disabled**:

| Trainer | `resample_steps` in config | Internal tracking active? |
|---------|---------------------------|--------------------------|
| PAnnealTrainer | `None` (line 201) | `steps_since_active = None` (not init) |
| StandardTrainer | `None` (line 222) | `steps_since_active = None` (not init) |
| GatedSAETrainer | Not passed (no param) | No tracking code at all |
| TopKTrainer | Not passed (no param) | **Yes** — `num_tokens_since_fired` always runs |
| GatedAnnealTrainer | `None` (line 289) | `steps_since_active = None` (not init) |
| SpaDETrainer | Not passed (no param) | No tracking code at all |

Resampling code exists in Standard, PAnneal, and GatedAnneal but is gated behind `if self.resample_steps is not None` — since we pass `None`, it never activates.

### Dead Neuron Tracking: Only TopK

**TopKTrainer** is the only trainer that currently tracks dead neurons:
- `num_tokens_since_fired`: per-feature counter, always initialized (line 206)
- `dead_feature_threshold = 10_000_000`: feature is "dead" if hasn't fired in 10M tokens (line 204)
- `self.dead_features = int(dead_features.sum())`: absolute count, NOT fraction (line 221)
- Logged to W&B as `dead_features` via `self.logging_parameters` (line 207)

The other 5 trainers have **no active dead neuron tracking** — Standard/PAnneal/GatedAnneal have the mechanism but it's disabled (None), GatedSAE and SpaDE have no dead neuron code at all.

### Fix: IMPLEMENTED in `log_stats()` in `training.py` (lines 68-74)

Added lazy-initialized running tracker after `f` is obtained. Works for ALL 6 trainers without modifying any individual trainer:

```python
# Dead neuron tracking: cumulative fraction of neurons that have
# never activated across all logged batches so far.
if not hasattr(trainer, '_neuron_ever_fired'):
    trainer._neuron_ever_fired = t.zeros(f.shape[-1], dtype=t.bool, device=f.device)
trainer._neuron_ever_fired |= (f != 0).any(dim=0)
frac_dead = 1.0 - trainer._neuron_ever_fired.float().mean().item()
log["frac_dead_neurons"] = frac_dead
```

Logged to W&B as `frac_dead_neurons` for all SAE types. The metric is monotonically decreasing — once a neuron fires, it stays marked alive. With `log_steps=5` over 36,621 training steps, this samples ~7,324 batches of 8,192 = ~60M activation vectors, more than sufficient to detect truly dead neurons.

## Discussion Notes

### SpaDE Training Speed vs ReLU

SpaDE likely needs more data/steps to converge than ReLU-based SAEs because:
1. Sparsemax on squared distances creates a more complex optimization landscape than ReLU
2. SpaDE learns geometric positioning (Voronoi-like structure), not just linear directions
3. The distance-weighted L1 regularizer couples reconstruction and sparsity — decoder atoms need to be well-positioned before the regularizer gives useful gradients
4. More interacting parameters (learned lambda, gamma, encoder/decoder atom positions)

If W&B curves show SpaDE MSE still decreasing at end of training while baselines have plateaued, consider increasing training steps for SpaDE only.

### Cosine Similarity as Alternative Distance Metric

Considered replacing Euclidean distance with cosine similarity: `sparsemax(λ * cos(x, Ae_j))`.

**Pros:**
- Cosine is bounded [-1, 1] → pre-sparsemax values naturally O(1), no lambda scaling issues
- Scale-invariant → standardization becomes less critical
- Easier optimization, likely faster convergence

**Cons:**
- Loses the Euclidean distance-based locality (Voronoi cell structure) — the core thesis of SpaDE
- Cosine-sparsemax is essentially a standard linear encoder with sparsemax activation (since `W @ x` with normalized vectors = cosine similarity)
- Would need to rethink the regularizer (e.g., `(1 - cos(x, Ad_j)) * f_j` instead of `||x - Ad_j||² * f_j`)
- Result would be closer to a Gated SAE with adaptive sparsity than to SpaDE

**Conclusion:** Would be informative as an ablation (does the distance metric or the sparsemax activation matter more?), but would lose SpaDE's unique contribution. Better to first try making Euclidean-SpaDE converge faster via warm-starting atoms with k-means, fixing lambda, or using larger learning rates for atom positions.

### Diagnostic Plot: Pre-Standardization Activations

The diagnostic script (`plot_norm_diagnostics.py`) correctly captures both pre- and post-standardization norms despite the training pipeline standardizing activations. It does this by creating a **raw** `NNsightActivationBuffer` (not wrapped in `StandardizedBuffer`), collecting raw activations, then computing standardization in-memory. The `StandardizedBuffer` wrapper is only applied during training in `train_karvonen_matched.py`.
